### 🔦 Highlights

#### New repositories start without public bootstrap peers

This build initializes new repositories with `Bootstrap=[]` and `AutoConf.Enabled=false`. DNS resolver, delegated router, and delegated IPNS publisher lists also start empty, so automatic configuration does not fetch public infrastructure defaults. Add your own bootstrap nodes with `ifshare bootstrap add <multiaddr>`. Existing repository configurations are unchanged.

To opt out of these initialization defaults and join the public network, use `ifshare init --profile=autoconf-on`, or `ifshare config profile apply autoconf-on` for an existing repository. To disable automatic configuration and clear the endpoints again, run `ifshare config profile apply autoconf-off`.

An empty bootstrap list is not network isolation. For a private swarm, distribute the same `swarm.key` to every node and follow the [private network setup](../experimental-features.md#private-networks).

#### Build and install the ifshare executable

`make build` now creates `cmd/ipfs/ifshare` (`ifshare.exe` on Windows), and `make install` installs that executable into `GOBIN` or `GOPATH/bin`. CLI usage, startup messages, command examples, version labels, and shell completions use `ifshare`. RPC command-list names and version response encoders retain their existing format. The CLI test harness uses the renamed executable. Legacy sharness scripts can still explicitly build the `cmd/ipfs/ipfs` compatibility target, and the container retains an `ipfs` alias for its existing entrypoint.

See the [private network deployment and handover guide](../private-network-zh.md) for key generation, bootstrap configuration, service management, and acceptance checks.
